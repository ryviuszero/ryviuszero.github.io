# Python 异步 IO 学习笔记（更好理解版）

## 一、为什么要折腾异步 IO？

先想一个很常见的场景：

在传统的同步模型里，程序是这么干活的：

请求1 → 等待 → 返回  
请求2 → 等待 → 返回  

问题就出在这个“等待”上。

当程序在等网络请求、读磁盘的时候，CPU 其实啥也干不了，只能干等着——就像你点了外卖，但非要站在门口等骑手，一步都不走。

这就很浪费。

而异步 IO 想解决的，就是这个问题：

👉 **在等待 IO 的时候，去干点别的事。**

换句话说，让程序“别闲着”，从而提升整体吞吐量。

---

## 二、几个核心概念，先搞清楚

### 1. 同步 / 异步 / 并发 / 并行

这些词很容易混在一起，我们简单理一下：

- **同步**：一步一步来，必须等前一个结束  
- **异步**：不用等结果，先往下走  
- **并发**：看起来同时处理多个任务（其实是来回切换）  
- **并行**：真正同时执行（多核 CPU）

很多人一开始会误解：

👉 **Python 的 asyncio，本质是“单线程并发”，不是并行。**

---

### 2. 协程（Coroutine）

协程可以理解成一种“很听话的函数”。

```python
async def foo():
    return 1
```

它和普通函数最大的不同在于：
	•	调用它不会立刻执行
	•	会返回一个 coroutine 对象
	•	必须交给事件循环来跑

你可以把它理解成：

👉 一个可以随时暂停、再继续执行的函数。

⸻

3. await 到底在干嘛？

```python
result = await foo()
```

很多人刚接触会觉得它很“魔法”，其实可以拆成三步：
	1.	暂停当前协程
	2.	把控制权让出去
	3.	等结果回来，再继续执行

听起来是不是很像：

👉 “我先去干别的，等你弄好了再叫我”

这就是典型的非阻塞等待。

⸻

4. 事件循环（Event Loop）

如果说协程是演员，那事件循环就是导演。

``` Python
import asyncio

async def main():
    print("hello")

asyncio.run(main())
```

事件循环主要干三件事：
	•	调度协程
	•	管理任务队列
	•	监听 IO 事件（比如 epoll / kqueue）

可以简单理解为：

👉 整个异步系统的大脑。

⸻

三、程序到底是怎么跑起来的？

一个 async 程序，实际执行流程是这样的：
	1.	创建协程
	2.	注册到事件循环
	3.	遇到 await → 挂起
	4.	切去执行别的协程
	5.	IO 完成 → 回来继续执行

这里有个关键词很重要：

👉 协作式调度（cooperative scheduling）

也就是说：
不是系统强制切换，而是“你自己在 await 的时候主动让出执行权”。

⸻

四、Task 和 Future，别再搞混了

Task 是什么？

task = asyncio.create_task(coro())

Task 可以理解为：

👉 “被事件循环接管的协程”

它的作用很简单：
	•	把 coroutine 注册到事件循环
	•	并且立即开始执行（不会阻塞）

⸻

Future 又是什么？

```Python
future = asyncio.Future()
future.set_result(42)
```

Future 表示：

👉 “一个未来才会有结果的东西”

不过现实中你很少手写它，通常都是框架在底层帮你用。

⸻

五、几种常见的并发写法

1. create_task（最推荐）

```Python
t1 = asyncio.create_task(foo())
t2 = asyncio.create_task(bar())
```

await t1
await t2

特点很简单：

👉 一创建就开始跑，真正并发。

⸻

2. gather（最常用）

```Python
results = await asyncio.gather(foo(), bar())
```

它的特点是：
	•	自动并发执行
	•	返回结果列表
	•	有异常会直接抛出来

适合“我要一口气拿到所有结果”的场景。

⸻

3. as_completed（更灵活）

```Python
for coro in asyncio.as_completed(tasks):
    result = await coro
```

谁先完成就先处理谁。

👉 特别适合爬虫、批量请求这种场景。

⸻

六、实际开发中最常见的用法

1. 异步 HTTP 请求

```Python
import httpx

async def fetch(url):
    async with httpx.AsyncClient() as client:
        r = await client.get(url)
        return r.text
```

如果你以前是用 requests，那这个就是它的异步版本。

⸻

2. 控制并发（非常重要）

```Python
sem = asyncio.Semaphore(5)

async def fetch(url):
    async with sem:
        ...
```

为什么要限流？

不然你很可能会：
	•	被对方服务器封 IP
	•	或者直接把服务打挂

👉 异步不是“越多越好”，而是“可控的多”。

⸻

3. sleep 的坑

# ❌ 错误
time.sleep(1)

# ✅ 正确
await asyncio.sleep(1)

一个会阻塞整个程序，一个不会。

这个坑，几乎每个人都会踩一次。

⸻

七、异常处理也有讲究

```Python

try:
    await foo()
except Exception as e:
    print(e)
```


如果用 gather：

await asyncio.gather(a(), b(), return_exceptions=True)

👉 可以避免一个任务挂掉，导致全部崩掉。

⸻

八、几个非常常见的误区

❌ 异步一定更快？

不一定。

👉 只有 IO 密集型任务，收益才明显。

⸻

❌ 能完全替代多线程？

不行。

类型	推荐方案
IO 密集	asyncio
CPU 密集	multiprocessing


⸻

❌ 可以无限并发？

await asyncio.gather(*[fetch() for _ in range(100000)])

这样写很危险：
	•	内存直接爆
	•	socket 被耗尽

👉 现实世界里，一定要“限流”。

⸻

九、底层其实没那么神秘

asyncio 底层依赖：
	•	Linux：epoll
	•	macOS：kqueue
	•	Windows：IOCP

本质就是：

👉 用 select / poll 监听 socket 状态

当 IO 准备好了，再回来执行对应的协程。

⸻

十、在 Web 开发里的应用

1. FastAPI

```Python

from fastapi import FastAPI

app = FastAPI()

@app.get("/")
async def read_root():
    return {"msg": "hello"}
```

为什么它这么火？
	•	天生支持 async
	•	高并发能力强

⸻

2. 异步数据库

比如：
	•	asyncpg（PostgreSQL）
	•	aiomysql

整条链路都是 async，性能才会真正发挥出来。

⸻

十一、一些经验之谈
	•	不要在 async 代码里混入阻塞操作
	•	实在要用，可以丢到线程池：

loop.run_in_executor()


⸻

	•	建议分层设计：

Controller（async）
↓
Service（async）
↓
IO 层（async）


⸻

	•	超时控制很重要：

await asyncio.wait_for(task, timeout=3)


⸻

	•	优雅关闭任务：

task.cancel()


⸻

十二、学习路径建议

如果你是刚入门，可以按这个顺序来：
	1.	async / await 基础
	2.	asyncio API（task / gather）
	3.	写几个 HTTP 请求
	4.	学会控制并发（Semaphore）
	5.	写一个简单爬虫
	6.	再上 FastAPI 项目

⸻

十三、最后一句话总结

如果只记一件事：

👉 异步 IO 的本质，是用事件循环调度协程，在等待 IO 的时候去做别的事。

再补三句“保命口诀”：
	•	async ≠ 多线程
	•	只对 IO 密集有用
	•	并发一定要控制
